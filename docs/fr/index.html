Écris le ticket. Il revient fait.

Un harnais autour de Claude Code qui exécute tes tâches sur ta machine — code, rédaction, actions, publications.

Écris le ticket sur le tableau de Ponos — la console, ou un dossier de fichiers Markdown. Il te rapporte une pull request, un texte, une action menée à bien ou une publication prête à partir. Tu réponds d’un mot, même depuis ton téléphone, et rien ne part sans ton oui.

Libre et gratuit, MIT · Linux · macOS · Python et git · Demande Claude Code — Notion et GitHub sont facultatifs.

Comment ça marche

Toute la boucle, en quatre gestes.

Deux sont les tiens, de quelques secondes chacun. Les deux du milieu sont ceux de Ponos.

  1. 01 · toi

    Tu écris le ticket

    Ce que tu dirais à un collègue, sur ton tableau — puis tu le passes en Ready.

  2. 02 · Ponos

    Ponos le fait

    Pendant que tu fais autre chose : une pull request sur sa propre branche, un texte écrit dans le ticket, une action menée à bien.

  3. 03 · toi

    Tu lis, et tu réponds d’un mot

    Une question ou un résultat t’arrive — dans la console, ou sur ton téléphone. oui est une réponse complète.

  4. 04 · Ponos

    Il livre

    Passe-le en Validated : la pull request est fusionnée, la publication est mise en ligne — et c’est seulement alors qu’il est Done. Tu as changé d’avis ? Cancelled le range, sans jamais l’exécuter.

Pourquoi lui confier

Trois choses qu’il fait et qu’une liste de tâches ne fait pas.

Il demande d’abord

Un doute l’arrête.

Un ticket sans type est classé avant de s’exécuter, et une hésitation te le renvoie avec la question. Une action s’arrête au premier doute — un mauvais compte, une valeur que le ticket ne donne pas — plutôt que d’agir au jugé.

Objectifs

À quoi servent les tickets.

Un objectif a un critère et une échéance, et les tickets qui lui sont liés comptent pour lui : « 3 tickets sur 7 terminés », au-dessus d’une barre, Late une fois le jour passé. Les idées sont proposées en en tenant compte.

Coffre

Des clés, jamais dans le ticket.

[vault] lit les jetons là où ils vivent déjà — l’environnement, le trousseau, pass, Bitwarden — et ne donne à chaque projet que les siens. La session en connaît les noms, jamais les valeurs, et une valeur affichée est masquée.

Plannings

Des tickets qui reviennent.

Chaque lundi, passe les dépendances en revue — un planning écrit le ticket et le passe en Ready tout seul, et la console dispose les suivants dans un calendrier. Une machine éteinte une semaine se réveille avec un ticket, pas sept.

La console

Un tableau à lui.

Ponos n’a besoin du tableau de personne. La console, sur 127.0.0.1, est l’endroit où tu écris un ticket, le glisses vers Ready et regardes sa session en direct — avec, à côté, un chat avec tout ton espace de travail. Dessous, le tableau est un dossier de fichiers Markdown : grep, ton éditeur et git le lisent aussi.

Notion

Ton tableau dans Notion.

Les tickets sont des lignes d’une base Notion : partage une page avec une intégration Notion, et init construit le reste dessous. Ponos lit les tickets que tu y écris, et répond sur la même page.

$ ponos init https://www.notion.so/ta-page --token -

Tu écris là où tu travailles déjà. Les tickets sont des lignes d’une base Notion ; leur Project pointe vers le dépôt — ou vers aucun, pour un texte.

Il rend compte sur le ticket lui-même. Chaque passe laisse un journal replié dans la page — chaque fichier lu, chaque commande lancée, ce qu’il a dit — et un commentaire avec la pull request, la durée et le coût.

Un texte revient en texte. Notes de version, newsletter, post : écrits directement dans le ticket, prêts à copier.

Ta colonne est le feu vert. Glisse la carte vers Validated : il fusionne ou publie. Pas avant.

Installation

Une commande.

Elle vérifie ce que ta machine a, dit ce qui manque et comment l’installer, démarre Ponos et ouvre sa console dans ton navigateur. Tout le reste se passe là.

$ curl -LsSf https://raw.githubusercontent.com/hermez-agency/ponos/main/install.sh | sh

Ensuite, la console te guide

Sur http://127.0.0.1:8787, une première connexion par étapes, chacune vérifiée pour de bon avant la suivante : la langue, ton mot de passe, qui répond aux sessions, Notion — colle le jeton, ajoute Ponos à une page, le tableau se construit dessous —, GitHub en un clic, un premier projet, et un ticket de démonstration joué sur-le-champ pour prouver que tout marche.

Pas de Notion ? Le tableau peut être un dossier de fichiers Markdown : Ton tableau dans Notion dit les deux.

Ce qu’il lui faut

  • Linux ou macOS — systemd ou launchd le maintiennent en marche, et sans l’un ni l’autre la console démarre quand même. Sous Windows, WSL convient sans minuteur : un ticket part quand la console le lance, ou avec ponos run ;
  • python3 ≥ 3.11 — ses quatre dépendances, httpx, pydantic, FastAPI et uvicorn, vont dans un environnement à lui, créé par l’installeur ;
  • l’accès réseau à PyPI pendant l’installation, pour les récupérer (et à uv, depuis GitHub, quand la machine ne peut pas installer un paquet) ;
  • git et Claude Code, que l’installeur propose d’installer ;
  • gh est facultatif : la console connecte GitHub en un clic.

Ce qui manque est nommé avec la commande qui l’installe ; relance ensuite la ligne ci-dessus.

Installer sur un serveur, avec Dokploy

Ponos est dans le catalogue de modèles de Dokploy : HTTPS sur un domaine à lui, et tes données sur des volumes nommés, qu’un redémarrage ou une nouvelle version conserve.

  1. Crée-le. Dans Dokploy, Templates › cherche Ponos › Create. Le domaine, le mot de passe et le jeton sont générés pour toi.
  2. Donne-lui un moyen de joindre Claude — la seule chose obligatoire — dans l’onglet Environment : le jeton qu’affiche cette commande, dans CLAUDE_CODE_OAUTH_TOKEN, ou une clé Anthropic dans ANTHROPIC_API_KEY. 
    $ claude setup-token
  3. Déploie, et ouvre le domaine. Connecte-toi avec PONOS_WEB_EMAIL et PONOS_WEB_PASSWORD, visibles dans l’onglet Environment. La console dit ce qui manque encore.

Questions, réponses

Ça ne marche pas — par où commencer ?
  • L’installeur s’est arrêté. Il a affiché ce qui manque et la commande qui l’installe : lance-la, puis relance la ligne d’installation.
  • La console ne s’ouvre pas. Va toi-même sur http://127.0.0.1:8787 ; si rien ne répond, ponos serve la démarre et dit pourquoi elle ne peut pas.
  • Notion ne trouve aucune page. La page doit être partagée avec l’intégration : ··· en haut à droite → Connections → ton intégration. La console la voit en quelques secondes.
  • Le ticket de démonstration échoue. La console montre ce que la passe a dit ; Run the full diagnosis sur le récapitulatif — ou ponos doctor dans un terminal — vérifie tout, et c’est le texte à coller pour demander de l’aide.

Que met en place le modèle Dokploy, et que puis-je ajouter ?

Les trois étapes sont plus haut. L’image embarque tout ce dont un ticket a besoin — Claude Code, git, gh, Node —, figée sur la version avec laquelle le modèle a été publié, et tourne sous un utilisateur à elle, jamais root. Quatre volumes nommés gardent la configuration et le tableau, les clones, et les connexions de Claude Code et de gh ; un healthcheck interroge /healthz ; la mémoire est plafonnée à 4 Go.

  • Obligatoire : CLAUDE_CODE_OAUTH_TOKEN (ton abonnement) ou ANTHROPIC_API_KEY.
  • Facultatif : OPENROUTER_API_KEY pour tous les autres modèles ; GH_TOKEN pour les pull requests — ou une GitHub App, créée depuis la console ; PONOS_NOTION_TOKEN pour un tableau dans Notion — sans lui, le tableau est en fichiers Markdown ; PONOS_TELEGRAM_TOKEN et PONOS_SLACK_TOKEN pour ton téléphone.
  • Générées ou à définir : PONOS_WEB_EMAIL, PONOS_WEB_PASSWORD et PONOS_WEB_TOKEN ; PONOS_LANGUAGE, en ou fr ; TZ, le fuseau dans lequel les heures d’un planning sont lues.

Un Dokploy sans Ponos dans son catalogue l’importe : un service Compose, Advanced › Import, et le Base64 que la documentation affiche.

Comment joindre Ponos depuis mon téléphone, loin de mon bureau ?

Avec Tailscale : un réseau privé entre tes propres appareils, gratuit pour un usage personnel. Aucun port ouvert sur Internet.

  1. Tailscale sur la machine qui fait tourner Ponos. Crée un compte, puis sous Linux : 
    $ curl -fsSL https://tailscale.com/install.sh | sh
$ sudo tailscale up
  2. Tailscale sur ton téléphone. L’application, connectée au même compte.
  3. Sers la console sur ton tailnet. Elle n’écoute que sur 127.0.0.1:8787 — exprès, puisqu’elle lance des sessions qui exécutent du code — donc l’adresse 100.x de la machine ne l’atteint pas. Tailscale fait le relais à la place, en HTTPS : 
    $ sudo tailscale serve --bg 8787
    Il affiche l’adresse, https://<machine>.<tailnet>.ts.net. La première fois, il peut te demander d’activer HTTPS pour ton tailnet.
  4. Donne ce nom à Ponos. Dans la configuration (ponos config), ou Settings › Public address dans la console : 
    # [web]
url = "https://<machine>.<tailnet>.ts.net"
    La console répond à ce nom, et à celui-là seulement ; sans lui, un 421. Aucun redémarrage nécessaire.
  5. Ouvre l’adresse sur ton téléphone, et connecte-toi comme sur la machine — ton e-mail et ton mot de passe, ou le jeton (ponos serve --print-token).

Jamais tailscale funnel. Funnel met la console sur l’Internet public, et derrière elle se trouve un runner qui exécute du code sur ta machine. Reste sur ton tailnet.
